## 🔴 重大教訓：Don't Touch Gateway Auth / Channels Without Full Plan

### 發生了什麼
05/24 session 中我為了修 Discord 通訊問題，自行補上 openclaw.json 的 channels.discord 區段後，用 SIGUSR1 重啟 gateway，結果：
1. Gateway in-process restart 產生新 runtime auth token（未 persist）
2. Agent session 用舊 token → 全部連線失敗 (unauthorized)
3. 訊息斷在執行中途，無法 recover

### 根因
- **Gateway auth token 沒有 persist** — 每次 restart 就變，除非明確設定 `gateway.auth.token`
- **SIGUSR1/SIGUSR2 重啟不會 preserve runtime token**，會重新產生
- 我修改了 config 但沒考慮到 auth token 連帶影響
- 備份檔（.bak / .rootbak）也全都是 `channels: {}` 空狀態，無法 rollback

### 未來規則 🚫
1. **永遠不要直接 restart gateway 來測試 config 變更** — 告知 Ryan，讓他手動重啟 container 最安全
2. ✅ **Gateway auth token 已 persist（2026-05-25）** — 已設定固定 token，restart 不再斷線
3. 修改 config 前先備份：`cp /home/node/.openclaw/openclaw.json /home/node/.openclaw/backups/`
4. SIGUSR1/SIGUSR2 在 container 環境不可靠 — container restart 才是正確方式
5. `safe-config.sh` 可自動備份 + 提醒
