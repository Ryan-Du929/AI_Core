# [流程] 避免一次性大量修改程式碼

- **日期：** 2026-05-19
- **作者：** Lucas
- **相關任務：** T09

## 發生什麼事
Ryan 要求修改八雲的提醒機制、稱呼、轉交流程等 7 個項目。我一次改了太多檔案，輸出內容太長，導致 OpenClaw session 因 idle timeout 而中斷，修改未完全生效。

## 根本原因
1. 一個工具呼叫內塞了太多操作（sed、讀檔、寫檔、重啟）
2. 輸出內容超過模型單次能處理的量
3. 沒有分批、分步驟執行

## 改善措施
1. 任何修改任務先拆成 T09.01 ～ T09.11 的小項目
2. 一次只改一個檔案的一個區塊
3. 每次修改後輸出簡短狀態，確保 session alive
4. 完成一個項目後更新 task_09.md 的狀態

## 如何避免再犯
- 任務拆到不能再拆才開始做
- 每個工具呼叫後都輸出至少一行文字
- 複雜修改先用 read 確認現狀，再用 edit 單點修改
