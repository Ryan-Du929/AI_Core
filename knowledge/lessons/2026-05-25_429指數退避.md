# [Lessons Learned] 429 Rate Limit Exponential Backoff 實作
- **日期：** 2026-05-25
- **作者：** Lucas
- **相關任務：** lucas_api.js v3.1

## 發生什麼事
NVIDIA DeepSeek API 在高併發呼叫時會回傳 HTTP 429（Rate Limit），原先的程式直接拋錯，沒有重試機制，導致任務全部失敗。

## 根本原因
- 原先 fetch 沒有處理 429，只檢查 `resp.ok`
- 沒有 retry logic，遇到限流直接放棄
- 沒有 sleep 間隔，無法等待限流解除

## 改善措施
在 `lucas_api.js` v3.1 中實作 `safeFetch()`：
- 偵測 HTTP 429 → 5 秒後重試 → 15 秒後重試 → 放棄
- 最多重試 3 次
- 使用 wrapper function 遞迴呼叫，不影響其他 HTTP 狀態碼的處理
- Error Middleware 確保最終失敗時回傳標準 500 JSON

## 如何避免再犯
- 任何外部 API 呼叫都應內建 retry + backoff 機制
- retry 策略統一為：5s → 15s → 放棄（3 次上限）
- timeout 用 AbortController，與 retry 獨立設計
