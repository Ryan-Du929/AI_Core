# 🔄 多模型接入評估方案

> 建立: 2026-05-20 | 作者: Lucas

---

## 目前已有的 API

| 提供者 | 模型 | 可用 Key | 用途 |
|--------|------|----------|------|
| NVIDIA NIM | DeepSeek V4 Flash | ✅ | Lucas 主要模型 |
| Groq | Llama/Gemma 等免費模型 | ✅ | 八雲 fallback |
| (待申請) OpenAI | GPT-4o / GPT-4o-mini | ❌ | 高品質備援 |
| (待申請) Anthropic | Claude Sonnet / Opus | ❌ | 複雜推理 |

## 分層策略（提案）

```
層級 1 — 簡單任務 → Groq（免費，快）
  適合：確認狀態、轉傳訊息、格式轉換

層級 2 — 一般任務 → DeepSeek V4 Flash（目前主模型）
  適合：程式開發、任務拆解、技術討論

層級 3 — 複雜任務 → GPT-4o / Claude（需申請）
  適合：架構設計、系統分析、長文件處理
```

## 每層的考量點

| 層級 | 速度 | 品質 | 成本 | 適合 |
|------|------|------|------|------|
| 1 | ⚡快 | 普通 | 💰免費 | 簡單回應、確認 |
| 2 | ⚡快 | 好 | 💵中 | 日常開發 |
| 3 | 🐢中 | 極好 | 💸高 | 關鍵決策 |

## 建議路線
1. **短期** — DeepSeek V4 Flash 為主，Groq fallback
2. **中期** — 申請 OpenAI API Key，接入 GPT-4o-mini 作為第 2 層備援
3. **長期** — 評估 Claude 接入，用於高複雜度架構討論

## 現有問題
- DeepSeek 429 Rate Limit — 需要 retry 機制或切換邏輯
- Groq 免費 TPM 上限 — 無法應付大量串流
- 無跨模型 routing 中間層
